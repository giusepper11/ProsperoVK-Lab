# Vulkan capability and test coverage

M0 selection matrix for the [pinned Vulkan 1.4.369 specification][spec], [VK-GL-CTS 1.4.6.2][cts], and [Vulkan Samples snapshot][samples]. A CTS name ending in `.*` denotes a group. Lab IDs are proposals. The console observations below are from upstream and refer to the revisions in the [audit](UPSTREAM.md).

For each target run, record these distinct facts:

1. **Advertised** is what instance and physical-device queries report, including API version, extensions, feature bits, queue flags, limits and format properties.
2. **Eligible** means those reports satisfy the case's Vulkan version or extension predicates, feature bits, selected queue, format usage, memory compatibility and resource budget.
3. **Enabled** records the API path, extensions, feature chain and queues selected when instance and device creation succeed.
4. **Validated** requires a completed case with status, output, oracle and identified target. An eligible execution can fail. A missing prerequisite yields `UNSUPPORTED` with a reason. A missing run yields `NOT_RUN`.

In the table, Linux refers to the lab's software-ICD feasibility run unless stated otherwise. The two M0 compute workloads passed on Slim 13.60. Other Slim cases remain `NOT_RUN`. Upstream absence reports apply to the stated upstream driver and platform.
